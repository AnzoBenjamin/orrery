# Design: Platform foundation

## Overview

Orrery runs as four processes around one Postgres database and one object store:

```
One CPU-only VPS:

Browser ──HTTPS──► kamal-proxy ──► Web app (TanStack Start)
   │  (SAM 2.1 part outlining runs here, on the visitor's GPU)
   │                 │  server functions, Better Auth, SSE, webhooks
   │                 ▼
   │              PostgreSQL 18 ◄──── Worker (pg-boss)
   │                 ▲                     │ dispatch (service token)
   │                 │ callbacks (HMAC)    ▼
   │                 └──────────────── Engine (CPU, quota nproc − 1)
   │                                       │
   └──── multipart upload / presigned GET ─┴──► Garage (S3 API)

Supporting services on the same VPS: Postfix + OpenDKIM (outbound SMTP), GlitchTip + Valkey (errors),
OTel Collector → OpenObserve (metrics, logs, traces), Gatus (uptime), CNCF Distribution registry.
Off the VPS: pgBackRest repo2 over SFTP and an rclone mirror of Garage buckets, on a machine the team controls.
```

- The web app owns all persistence. The engine is stateless compute that reads inputs and writes artifacts through presigned URLs and reports results through signed callbacks.
- The worker is the only caller of the engine. It turns domain actions into engine jobs and retries safely.
- Realtime progress flows engine → callback → Postgres (event log + `NOTIFY`) → SSE → browser.

## Components

### Configuration (`packages/config`)

- `@t3-oss/env-core` with Zod schemas per process (`webEnv`, `workerEnv`) and `pydantic-settings` for the engine.
- Public browser variables are prefixed `PUBLIC_` and validated separately.

### Database (`packages/db`)

- `drizzle-orm` with `node-postgres` pool. A second, direct `pg` client is created only inside `packages/db/src/notify.ts` for `LISTEN`, wrapped in a typed API (`subscribe(channel, handler)`).
- Query modules per aggregate: `specimens.ts`, `footage.ts`, `analyses.ts`, `mechanisms.ts`, `resurrections.ts`, `exports.ts`, `shares.ts`, `benchmarks.ts`. Each exports functions that take a `Tx` and typed inputs.
- `assertMigrationsApplied()` compares the drizzle migration journal with `__drizzle_migrations` at boot.

Core tables owned by this spec (domain tables for later specs are listed in their designs):

| Table | Purpose |
|---|---|
| `user`, `session`, `account`, `verification`, `passkey` | Better Auth (generated by the Better Auth CLI into Drizzle schema) |
| `user_preference` | email opt-outs, sound preference, units preference |
| `specimen` | id, owner_id, title, description, cover_object_key, created_at, updated_at, deleted_at |
| `footage` | id, specimen_id, role (`reference`, `broken`, `repaired`, `supplementary`, `archival`), status (`uploading`, `probing`, `ready`, `rejected`), object_key, original_filename, byte_size, sha256, duration_ms, width, height, fps_nominal, is_vfr, codec, rotation_deg, rejection_reason, created_at |
| `upload_session` | id, footage_id, s3_upload_id, part_size, expires_at, completed_at |
| `share_link` | id, specimen_id, token_hash, scope (`read`), expires_at, revoked_at, created_by, last_used_at |
| `domain_event` | id (bigserial), specimen_id, type, payload jsonb, created_at. Feeds SSE replay |
| `notification` | id, user_id, kind, payload, read_at, created_at |
| `object_deletion` | id, object_key, attempts, last_error, completed_at |

### Authentication (`apps/web/src/server/auth.ts`)

- Better Auth with `drizzleAdapter(db, { provider: "pg" })`, plugins: `passkey`, `tanstackStartCookies` (last in the plugin list), rate limiting with database storage.
- `emailAndPassword: { enabled: true, requireEmailVerification: true }`, social providers GitHub and Google.
- Email callbacks call the email module. Sign-in alerts are sent from a Better Auth `databaseHooks.session.create.after` hook when the user agent and IP prefix are new for the user.
- Route guards: `beforeLoad` on authenticated route groups reads the session through a server function.

### Authorization (`apps/web/src/server/policy.ts`)

- `can(actor, action, resource)` with actors `user`, `share`, `admin`, `engine`. Resources resolve to a specimen ID and are checked by ownership or share grant.
- Every server function is built with a wrapper `authed(inputSchema, action, handler)` that validates input, loads the actor, applies the policy, opens a transaction, and maps errors. Handlers cannot skip the policy.
- Not-authorized and not-found both return `NotFound`.

### Uploads

- Client: Uppy core with `@uppy/aws-s3` (multipart mode), a custom UI in the design language (no Uppy dashboard). Resumes with Uppy's Golden Retriever plugin.
- Server functions: `createUpload`, `signPart`, `listParts`, `completeUpload`, `abortUpload`, backed by `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner`.
- On completion, the worker runs a `footage.probe` job that calls the engine's `/v1/probe` endpoint (PyAV/ffprobe), which validates the container, codec, duration, rotation, and variable frame rate, then marks the footage `ready` or `rejected` with a reason.
- A scheduled `uploads.reap` job aborts expired multipart uploads.

### Jobs (`apps/worker`)

- pg-boss with a direct connection. Queues: `footage.probe`, `analysis.dispatch`, `export.render`, `objects.delete`, `uploads.reap`, `email.send`, `benchmark.ingest`.
- Each queue has a definition object `{ name, schema, retryLimit, retryBackoff, expireInSeconds, singletonKey(payload) }`. A typed `enqueue(def, payload)` helper is the only way to publish.
- The admin operator page in the web app reads pg-boss tables through a typed module and offers retry and cancel.

### Realtime

- `domain_event` insert and `pg_notify('specimen:<id>', <event id>)` happen in the same transaction.
- SSE route `/api/specimens/$id/events` authorizes, subscribes, replays from `Last-Event-ID`, and sends heartbeats every 15 s.
- Client: a `useSpecimenEvents(id)` hook that updates the TanStack Query cache by event type.

### Engine contract (`packages/engine-contract`)

```ts
JobRequest = {
  contractVersion: "1",
  jobId: uuid, kind: "probe" | "reconstruct" | "diagnose" | "resurrect" | "verify" | "export",
  inputs: { footage?: PresignedGet[], mechanism?: MechanismGraph, params: KindParams },
  artifactGrant: { uploadUrls: Record<ArtifactSlot, PresignedPut> },
  callback: { url: string, secretRef: string },  // secret delivered via header, never logged
  traceparent: string,
}
EngineEvent = { jobId, seq, at, type: "stage_started" | "progress" | "stage_completed"
  | "input_required" | "artifact_written" | "completed" | "failed", payload }
```

- Callback signature header: `Orrery-Signature: t=<unix>,v1=<hex hmac>`. The web app verifies with a constant-time comparison and stores `(job_id, seq)` with a unique constraint for idempotency.

### Email (`packages/email`)

- React Email templates rendered server-side, sent with Nodemailer through the `email.send` queue.

### Observability

- `@opentelemetry/sdk-node` in web and worker, `opentelemetry-instrumentation-fastapi` in the engine, OTLP export to the configured collector.
- Sentry SDKs (MIT) for TanStack Start, Node, and Python, configured with GlitchTip DSNs.

### Security

- CSP with per-request nonce injected by TanStack Start middleware, `frame-ancestors 'none'` except on the share embed route, which allows any origin.
- Engine egress allowlist enforced in the HTTP client used for downloads.

## Error handling

- Domain errors are a discriminated union (`NotFound`, `Forbidden`, `Conflict`, `Invalid`, `RateLimited`, `Unavailable`) mapped to HTTP statuses at the server-function wrapper and to designed error states in the UI.
- Unexpected errors are reported to GlitchTip and shown to the user with a reference ID.

## Correctness properties

1. *For any* two users A and B and any server function, a call by B referencing A's resource returns `NotFound` and changes no rows. **Validates: 5.2, 5.4**
2. *For any* sequence of engine callbacks containing duplicates and reorderings, the persisted event log equals the deduplicated set ordered by `seq`. **Validates: 9.4**
3. *For any* callback body and timestamp, verification succeeds only with the correct secret and a timestamp within 5 minutes. **Validates: 9.3**
4. *For any* SSE disconnect point, reconnecting with `Last-Event-ID` yields exactly the events after that ID. **Validates: 8.2**
5. *For any* environment object, startup validation accepts it if and only if it satisfies the schema, and error output never contains secret values. **Validates: 2.1, 2.2**

## Testing strategy

- Unit: policy decisions, signature verification, env validation (fast-check for properties 3 and 5).
- Integration (Testcontainers Postgres + Garage): every query module, every server function's authorization (property 1), event replay (property 4), callback idempotency (property 2), multipart upload lifecycle.
- End-to-end (Playwright on the full stack): sign-up with Mailpit verification, password reset, passkey registration using Chromium's virtual authenticator, session revocation, account deletion, specimen create and delete, resumable upload with a forced network interruption, rejected upload with a disguised non-video file, share link open in a signed-out context, admin queue page.
